# 수영·운동 분석 도구

브라우저에서 바로 여는 단일 HTML 앱 두 개입니다. 설치나 서버가 필요 없고, 사진과 영상은 기기 안에서만 처리합니다.

| 앱 | 폴더 | 하는 일 |
|---|---|---|
| 스트림라인 자세 분석 | `streamline/` | 지상 스트림라인 측면 사진에 12개 점을 찍어 어깨 굴곡 부족, 팔꿈치·손목·골반·무릎 각도, 머리 위치, 허리 아치, 전체 일직선 편차를 계산합니다. 날짜별 기록 비교(추이 그래프, 관절선 겹쳐 보기)와 측정값·감별 테스트에 근거한 가동성 운동 추천이 들어 있습니다. |
| 동작 궤적·속도 분석 | `motion/` | 종목은 **스트림라인 / 돌핀킥 / 수영 스타트 / 중량 풀업 / CMJ / 기타** 6가지. **스트림라인(벽 푸시·글라이드)**은 골반(수영복)을 따라가 글라이드 중 수평 속도가 줄어드는 정도를 2차 항력 모형으로 맞춰 감속 계수 k·절반 속도 거리·속도 감소율·깊이 변화를 재고, 한 프레임에 손끝·머리·어깨·골반·무릎·발목을 찍으면(또는 AI로 찾으면) 손끝–발목 선에서 벗어난 거리와 어깨·골반·무릎 각도로 일직선 정도를 봅니다. **중량 풀업**은 턱을 추적해 반복별 이동 거리·평균 속도·속도 저하·파워, 바 높이를 찍으면 턱 넘김, 팔꿈치 각도로 끝까지 내려왔는지를 봅니다. CMJ는 골반과 발끝을 추적해 체공 시간 점프 높이, 반동 깊이, 이륙 속도, 이륙까지 시간, RSImod, 파워를 계산합니다. 기록 화면에서 풀업은 무게별 최고 평균 속도, CMJ는 높이 추이를 봅니다. **수영 스타트**는 머리(수모)·골반·앞다리 무릎·발목을 추적하고(앞발 발끝은 따라가지 않는 '이탈 띠'), 출발벽·수면을 찍어 출발대 이탈, 비행 시간, 입수 거리, 이탈 속도·각도, 입수 자세, 무릎·골반 각도(준비·밀 때 최소·이탈·입수)를 재고, 출발 신호·브레이크아웃을 지정하면 블록 시간과 브레이크아웃 거리·시간까지 봅니다. **돌핀킥**은 발목·골반을 추적해 킥 횟수, 템포, 진폭, 다운킥 비율·속도, 전진 속도, 킥당 전진 거리를 킥별로 봅니다. 바벨 등 기타 동작도 그대로 쓸 수 있습니다. |

## 여는 법
- `index.html`을 브라우저로 열거나, GitHub Pages를 켜면 `https://<계정>.github.io/<저장소>/`에서 열립니다.
- GitHub Pages나 파일로 열면 기록은 그 브라우저(localStorage)에만 저장됩니다. claude.ai 아티팩트로 열면 계정에 저장되어 폰과 컴퓨터에서 같은 기록을 봅니다.
- 동작 분석 기록에는 추적 결과(점 경로, 시각 0.00001초·위치 0.01px)까지 저장됩니다. 기록의 **영상 열어 점·시점 고치기**로 같은 영상을 고르면 다시 추적하지 않고 저장할 때 결과를 그대로 불러옵니다(영상 자체는 저장하지 않음). 추적 결과를 저장하기 전 기록은 저장해 둔 설정으로 다시 추적합니다.
- 점이 관절에서 벗어나면 결과의 **위치 고치기**를 켜고 프레임을 옮겨 가며 여러 점·여러 곳을 끌어 고친 뒤 **반영**을 한 번 누릅니다. 고친 점만 그 부근을 다시 추적하고(기존 경로와 다시 만나면 멈춤), 다른 점은 건드리지 않습니다.

## 계산 방식 요약
- **스트림라인**: 몸통선(골반→어깨) 기준으로 위팔의 앞 기울기를 어깨 굴곡 부족으로 봅니다. 손끝–복사뼈 직선에서 각 관절이 벗어난 거리의 RMS를 일직선 편차로 씁니다. 판정 기준(양호/주의)은 잠정값이며 검증된 규준이 아닙니다.
- **글라이드**: 2차 항력(dv/dt = −k·v²)이면 1/v = 1/v0 + k·t가 직선이므로, 가장 빠른 시점부터 다시 빨라지기 직전(첫 킥)까지 1/v를 시간에 직선 맞춤해 k(1/m)를 구합니다. 속도가 절반이 되는 거리는 ln2/k. k와 거리는 기준 길이에 따라 바뀌고(기준 길이가 2배 틀리면 k도 2배), 속도 감소율은 바뀌지 않습니다.
- **궤적·속도**: 찍은 점 주변 패치를 정규화 상관(ZNCC)으로 프레임마다 찾고, 프레임의 실제 시각(`requestVideoFrameCallback`)을 씁니다. 위치를 2차 Savitzky–Golay(앞뒤 약 0.06초)로 평활·미분해 속도를 구합니다. 파워는 무게×(중력+수직 가속)×수직 속도와, 간이값 무게×중력×최고 속도 두 가지를 보여 줍니다.

## 한계
- 손으로 찍는 점은 각도로 ±2~3° 오차가 있습니다. 같은 조건에서 찍은 본인 기록끼리 비교하는 용도가 가장 믿을 만합니다.
- 궤적 분석은 화면과 평행한 평면 안의 움직임만 잽니다. 카메라를 고정하고 옆에서 찍은 원본 영상이 필요하며, 화면 녹화본·편집본은 부정확할 수 있습니다.
- 속도를 아는 합성 영상(최고 2.34 m/s)에서 2.30~2.31 m/s로 측정됐습니다(평활에 따른 약 −1.5%). 실제 운동 영상과 다양한 폰에서는 아직 충분히 검증하지 않았습니다.
- 동작 분석의 추적은 두 방식입니다. **자세 인식(AI) + 무늬**: MediaPipe Pose(heavy, 영상 모드)로 프레임마다 관절을 찾고, 찍은 점과의 차이를 그 관절이 속한 뼈(허벅지·정강이·발·머리)의 방향 기준으로 유지한 채(몸이 돌면 차이도 같이 돎) 주변 몇 px을 무늬(정규화 상관)로 다듬습니다. 첫 프레임은 같은 화면을 3번 인식해 자리를 잡고, 왼·오른쪽 관절이 뒤바뀌어 인식되면 이어지는 쪽을 따라가며, 자세 위치의 무늬가 전혀 안 맞는데 무늬는 예측 자리에서 아주 잘 맞으면(손에 가린 관절 등) 무늬를 믿습니다. 실제 CMJ 영상에서 무늬만으로는 반동·체공 중 무릎·발목이 배경에 붙었지만 이 방식은 쪼그림 무릎 64°, 체공 174~178°, 착지 50°로 따라갔습니다. claude.ai 아티팩트에서는 모델을 받을 수 없어 공유 주소에서만 됩니다. **무늬만**: 밝기 정규화 상관, 처음·갱신·모아 둔 무늬(최대 6장), 놓치면 범위를 넓혀 다시 찾기, 화면 가장자리 부분 비교, 뼈로 이어진 점의 길이 제약(15% 넘게 바뀌면 다시 찾기). 합성 시험(tests/tracker.test.js)에서 이전 추적기가 끝에 55~60px 벗어난 장면을 5px 안으로 유지했습니다. 색 채널은 시험에서 오히려 1~4px 나빠져 기본으로 쓰지 않습니다.
- 합성 영상 검증: 풀업(3회, 0.55/0.53/0.50m)은 이동 거리 ±1cm, 평균 속도 −4~+2%, 턱–바 ±0.3cm. CMJ(정답 34.5cm)는 120fps 35.4cm, 60fps 34.3cm. 수영 스타트(비행 0.390초, 입수 2.65m)는 30~240fps에서 비행 ±1프레임, 입수 거리 ±1cm, 이탈 속도·각도는 비행 궤적 포물선 맞춤으로 ±0.1 m/s·±1°. 돌핀킥(2.2Hz, 진폭 45cm)은 템포 ±3%, 진폭 ±1cm, 전진 속도 ±0.01 m/s. 글라이드(v0 2.3 m/s, k 0.24/m)는 30~240fps·잡음·좌우 방향에서 k ±0.012, 끝 속도 ±0.03 m/s. 실제 영상(사용자 제공, 240fps 수중 옆모습): 돌핀킥은 자세 인식으로 발목·골반·무릎·어깨가 모두 연결되고 몸 뒤집힘 없이 킥 2회(완전 1회)를 찾았고, 스트림라인은 수영복 무늬만으로 골반을 끝까지 따라가 1/v 직선 맞춤 R² 0.99였습니다. 정답 값이 있는 실제 영상 검증은 아직 없습니다.
- 관절 각도는 합성 스쿼트 영상(힙 54–170°, 무릎 66–170°)에서 1° 이내로 맞았습니다. 매우 빠른 동작(4 m/s 이상)의 최고 속도는 평활 때문에 2~4% 낮게 나옵니다.
